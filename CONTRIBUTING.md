# Contributing to agy-rc

Thanks for taking the time to contribute! Issues and pull requests are welcome.

## Reporting bugs / requesting features

Open an issue using one of the templates. For bugs, please include your OS, Node
version (`node -v`), tmux version (`tmux -V`), the `agy` version, and the relevant
server log (`journalctl --user -u agy-rc -n 50`), with any tokens or personal paths
removed.

## Development setup

```bash
git clone https://github.com/fjguillen-96/agy-rc.git
cd agy-rc
npm install
cp .env.example .env      # adjust PORT / AGY_PROJECTS_ROOT as needed
npm run dev               # server with --watch on http://127.0.0.1:8787
npm test                  # Node's built-in test runner (tmux must be installed)
```

The frontend is vanilla JS served from `public/` (no build step); the backend is
Express 5 + `ws` in `server/`. `docs/CHAT.md` explains the `agy` stream-json
protocol the chat is built on.

## Pull requests

1. Fork the repo and create a branch from `main` (`git checkout -b fix/short-description`).
2. Keep PRs focused: one bug fix or feature per PR.
3. Add or update tests in `test/` when you change server behaviour. `npm test` must pass.
4. Match the surrounding code style (2 spaces, single quotes, ES modules, comments in the
   language of the file you are editing).
5. Use [Conventional Commits](https://www.conventionalcommits.org/) for commit messages
   (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
6. Fill in the pull request template and describe how you tested the change (device,
   browser, and whether you tried it from a phone over Tailscale if the change touches the UI).

CI runs `npm test` on Node 20, 22 and 24 for every PR.

## UI strings and translations

The UI is bilingual (Spanish / English). Source strings are written in Spanish and act as
the translation key: wrap every user-visible string with `t()` from `public/js/i18n.js`
(`t('Nuevo chat')`, `t('Máximo {n} adjuntos', { n })`) and add the English text to the `EN`
dictionary at the bottom of that file. Messages generated by the server carry a `key`
(`sys.*`) plus `params` and are translated on the client by `systemText()`. To add a new
language, add its code to `SUPPORTED` and a dictionary next to `EN`.

## Security issues

Please do **not** open a public issue for security vulnerabilities. Use GitHub's
private vulnerability reporting ("Report a vulnerability" under the Security tab)
instead.
